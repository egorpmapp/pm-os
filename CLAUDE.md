# PM-OS — инструкции для Claude

## Кто я
Я продакт-менеджер мобильных приложений. Зона ответственности:
- развитие приложений и роадмап;
- воронка **install → onboarding → paywall → trial → подписка → продление**;
- A/B-тесты онбордингов и пейволлов;
- ASO;
- исследования пользователей и конкурентов.

Стек: **Amplitude** (аналитика), **Firebase** и **Apphud** (A/B-тесты, Remote Config, подписки), **Slack**, **Figma**, **Google Drive** (документы).

## С чего начинать каждую сессию
1. **Всегда сначала читай `portfolio.yaml`**: это реестр всех проектов и приложений и всех ID (Amplitude, Apphud, Firebase, Drive, Slack).
2. Затем `projects/<проект>/project.md`, затем файлы нужного приложения.
3. Если нужного ID нет в `portfolio.yaml` (или там `TODO`), спроси меня. Не угадывай.

## Устройство репозитория
```
portfolio.yaml                       реестр проектов, приложений и ID
skills-sources.md                    происхождение сторонних скиллов
projects/<проект>/project.md         контекст проекта
projects/<проект>/_app-template/     шаблон приложения (не редактировать под конкретное приложение)
projects/<проект>/<slug>/            приложение: context.md, metrics.md, experiments.md
templates/                           шаблоны PRD, задач, дизайна и отчётов A/B-тестов, скиллов
.claude/skills/<имя>/SKILL.md        все скиллы, плоско
```
- Новое приложение добавляется только скиллом **add-app**.
- Сторонний скилл импортируется только скиллом **import-skill**.

## Где хранить результаты
- **Документы для людей** (отчёты, PRD, результаты тестов, исследования, брифы) сохраняются в **Google Drive**, в папку из `portfolio.yaml` (`drive_folder_id` / `drive_folder_path` проекта или приложения, с нужной подпапкой).
- В репозитории остаётся только то, что управляет работой Claude: контекст, метрики-бенчмарки, журнал экспериментов, шаблоны, скиллы.
- Если Drive недоступен, сохрани черновик в scratchpad и скажи мне, куда его положить. В git такие черновики не коммить.

## Правила (обязательные)
- **Аналитика и данные — только чтение.** Amplitude, Firebase, Apphud только читаем.
- **Ничего не менять** в Firebase, Apphud, Remote Config: не запускать и не останавливать эксперименты, не менять раскатку, не менять цены и продукты.
- **Не отправлять сообщения в Slack** (и вообще ничего не публиковать наружу) без моего явного подтверждения конкретного текста.
- **Ключи, токены, пароли никогда не коммитить.** Только переменные окружения или локальные файлы, которые в `.gitignore`.
- **Сырые выгрузки данных** (CSV, JSON-экспорты, дампы) в git не класть.
- Перед любым внешним действием с побочным эффектом спроси подтверждение.

## Формат отчётов
- Язык: **русский**.
- Сначала **вывод** (1–3 предложения), потом цифры, потом детали.
- Коротко, с конкретными числами: абсолютные значения, дельта, доверительный интервал или p-value, размер выборки, период.
- Всегда указывать источник данных (Amplitude-чарт, Apphud, Firebase) и дату выгрузки.

## A/B-тесты
- Дизайн теста делается по `templates/ab-test-design.md`, отчёт по `templates/ab-test-readout.md`.
- **После каждого завершённого A/B-теста** добавь запись **сверху** в `projects/<проект>/<slug>/experiments.md`: гипотеза, результат, значимость, решение, ссылка на отчёт в Drive.
- Если тест изменил норму метрики, обнови `metrics.md` приложения.

## Скиллы
- Все скиллы лежат плоско: `.claude/skills/<имя>/SKILL.md`, без вложенных папок.
- Имена в kebab-case. Сторонние скиллы сохраняют исходное имя, происхождение фиксируется в `skills-sources.md`.
- Новый собственный скилл делается из `templates/skill-template/SKILL.md`.
